# 授权与披露管理页面规划

候选人对"我的信用数据流向哪里"的完全控制台。多租户平台中，企业租户开启信用背书后，候选人投递时可选择披露量潮信用摘要——授权管理页让候选人看到每一笔披露并随时撤销。这是"付费与推荐结果隔离"与"复用提炼结果不共享原始记录"在客户端的落实。

## 页面结构

### 授权列表

- 每条授权：企业租户名称、披露时间、披露内容（信用等级/背书状态摘要）、当前状态
- 状态徽标：生效中 / 已撤销 / 已过期（投递流程结束后自动过期）

### 撤销操作

- 撤销按钮：生效中的授权可撤销
- 撤销确认：提示"撤销后该企业将不再看到您的信用摘要，已获取的摘要可能仍保留在其系统内"
- 撤销后企业端不可再访问摘要（平台层同步失效）

### 空状态与说明

- 无授权时：说明信用摘要的用途（企业更快了解你的能力背书）与获取方式（投递时选择披露）
- 说明披露边界：只披露摘要，不披露原始记录；摘要内容由平台统一生成

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 授权条目 | 列表（企业、披露时间、摘要内容、状态徽标） |
| 撤销按钮 | 生效中条目（确认弹窗） |
| 说明卡 | 页面底部（披露边界、撤销后果） |

## 数据与契约

- 数据源：`GET /authorizations`（列表）、`DELETE /authorizations/:id`（撤销）
- 模型：`Authorization`（企业租户、披露时间、摘要、状态、过期时间）
- 只读 + 撤销：候选人不能修改披露内容（摘要由平台统一生成，防止自夸式披露）

## 演进

- 阶段 3：授权管理上线（与企业租户信用背书开关配套）
