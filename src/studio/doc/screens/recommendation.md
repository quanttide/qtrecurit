# 结构化推荐信页面规划

这个页面的本质是一份**结构化的推荐信**：客观行为记录 + 我们的评价。评估通过的候选人获得可展示、可验证的信用背书，供求职者向其他企业展示。对应产品阶段二（选拔记录与信用背书）与阶段三（品牌商业化）。

## 内容原则

- 不展示考核标准与评估结论——主观判断不进入推荐信
- 主体是**客观行为记录**：候选人在我们这里实际做过什么，事实可验证
- 其次是**我们的评价**：署名评价（直接指导者、创始人），评价者的信誉为背书担保
- 记录是输入，推荐信是输出——选拔过程与结果沉淀为事实

## 入口与鉴权

- 入口：候选人凭凭证查看自己的推荐信；分享链接或 PDF 供企业查看
- 鉴权：候选人本人可查；企业通过验证入口查证真伪
- 凭证由推荐信编号承载

## 页面结构

### 推荐信头部

- 推荐方：量潮招聘
- 被推荐人：姓名（或代号）、在组织中的身份（如实训生/实习生）
- 编号与评估时点：可追溯的推荐信标识

### 客观行为记录区

- 历史行为：在组织里做过哪些事情（时间、事项、结果）——事实可验证
- 实战记录：实战任务、过程与结果（连续多日任务执行，过程可见）

### 我们的评价区

- 直接指导者评价：署名评价，基于日常共事
- 创始人评价：署名评价，代表组织的背书
- 评价只针对共建者特质（踏实、责任心、留存意愿），不评价专业能力

### 验证与责任区

- 验证入口：企业扫码/链接查证推荐信真伪与事实
- 责任条款：推荐信反映评估时点状态，非未来担保
- 导出：PDF 版本供求职者发布

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 推荐信头部卡 | 页面顶部（推荐方、被推荐人、编号） |
| 行为记录条目 | 行为记录区（时间、事项、结果） |
| 实战记录条目 | 行为记录区（任务、过程、结果） |
| 署名评价卡 | 评价区（指导者、创始人，署名与身份） |
| 验证徽章与入口 | 页面底部（查证、责任条款、导出） |

## 数据与契约

- 数据源：`GET /recommendations/:id` → Recommendation（只读）
- 模型：Recommendation 聚合客观行为记录（BehaviorRecord：时间、事项、结果）与署名评价（Evaluation：评价者、身份、内容）
- 契约先行：字段以 `data/profile/qtrecurit/` 为基准，与 Provider API schema 同源

## 边界条款

- 优先录取权：评估出的人才优先加入自身，推荐信对象是「我们没名额但合格」的
- 内容范围：只记录客观行为与署名评价，不输出考核结论
- 责任条款：推荐信反映评估时点状态，非未来担保
