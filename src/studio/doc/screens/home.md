# 凭证查询首页页面规划

Studio 首页是候选人进入自己信用档案的入口。现状是"查看示例推荐信"按钮（`home_screen.dart`，mock 数据）；演进后为**凭证查询**——候选人凭查询凭证查看自己的真实档案，这是"付费与推荐结果隔离"在客户端的第一道闸门：凭证只对本人发放，档案只凭证据生成。

## 页面结构

### 品牌区

- 量潮招聘标识 + 副标题"结构化推荐信：客观行为记录与我们的评价"
- 产品说明：透明窗口理念——"你用同一套标准、同一套数据看自己"

### 凭证查询区

- 输入框：查询凭证（投递成功时或推荐信签发时发放）
- 校验：凭证格式、有效性、过期提示
- 查询成功 → 进入档案入口（评估记录、信任记录、推荐信、授权管理）

### 示例区（无凭证时）

- 保留示例推荐信入口（标注"示例"），供未获得凭证的访客了解产品形态
- 说明如何获得凭证（投递量潮招聘、被推荐时）

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 品牌头 | 页面顶部（标识、副标题） |
| 凭证输入卡 | 页面主体（输入、校验、错误提示） |
| 档案入口卡 | 凭证验证后（推荐信、评估记录、信任记录、授权管理） |
| 示例入口 | 无凭证时（示例推荐信，带"示例"标记） |

## 数据与契约

- 数据源：`POST /sessions/verify`（凭证 → 会话凭证，JWT 承载档案访问权）
- 模型：`Session`（凭证、过期时间、可访问的档案范围）
- 档案范围由凭证权限决定：推荐信凭证只开推荐信，档案凭证开全部

## 演进

- v0.1：凭证查询 + 示例保留；推荐信数据源换为 Provider API
- 阶段 2：档案入口按凭证权限展开（评估/信任/推荐信）
- 阶段 3：授权管理入口、多平台凭证（分享链接、PDF 导出）
