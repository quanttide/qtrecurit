# 评估记录与信任记录页面规划

候选人的透明窗口核心：凭查询凭证查看"我们如何评价你、依据什么"。评估记录（筛选标准化线）与信任记录（信任承载线）同构——筛选评估的产出即信任档案的记录（ROADMAP 共享契约），两个页面共用同一套记录条目组件。

## 页面结构

### 评估记录页（`/records/assessment`）

- 考核分层：实训生/实习生/长期共建者/短期打手——候选人所处层级与依据
- 问卷分析：问卷作答的评估结果与 AI 分析说明（考评方式透明）
- 政策匹配：与招聘政策的匹配结论

### 信任记录页（`/records/trust`）

- 历史行为：在组织里做过哪些事情（时间、事项、结果）
- 背调：背调记录（如有）
- 推荐信：已签发的推荐信列表（链接到推荐信页）

### 记录条目组件（共用）

- 每条记录：时间、事项、结果
- 状态徽标：已确认/待补充/已引用（被推荐信引用）
- 不展示：考核标准全文（标准公开在考评标准公开页）、主观结论

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 记录分组头 | 页面顶部（评估记录/信任记录分组） |
| 记录条目 | 分组内（时间、事项、结果、状态徽标） |
| 推荐信链接条目 | 信任记录内（已签发推荐信列表） |

## 数据与契约

- 数据源：`GET /records?type=assessment|trust`（只读，凭会话凭证）
- 模型：`AssessmentRecord`（考核分层、问卷分析、政策匹配）、`TrustRecord`（历史行为、背调、推荐信引用）
- 契约先行：评估字段与信任字段同构，与 Provider API schema 同源

## 演进

- v0.1：凭凭证查看评估记录与信任记录（对应 ROADMAP v0.1 候选人个人考评页）
- v0.2：合并为统一考评档案视图（标准 + 过程 + 结果 + 信任）
- 阶段 3：记录被推荐信引用后的"证据链"展示（记录 → 推荐信 → 披露摘要）
