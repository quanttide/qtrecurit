# ROADMAP — qtrecurit Studio

qtrecurit Studio 是**候选人的透明窗口**——透明公开我们如何考评，让候选人用同一套标准、同一套数据看自己。版本目标与并行逻辑见仓库根 `ROADMAP.md`。

## 版本目标

| 版本 | 内容 | 对应产品阶段 |
|------|------|-------------|
| v0.1 | 考评标准公开 + 候选人个人考评页（推荐信真实化） | 阶段一 + 阶段二 |
| v0.2 | 统一考评档案视图与导出 | 阶段一 × 阶段二 |
| v0.3+ | 市场担保与信用展示（授权披露、企业查证） | 阶段三、阶段四 |

## v0.1：透明公开考评

- 考评标准公开页：考核分层（实训生/实习生/长期共建者/短期打手）、序列轨道（T0/T1/T2、A/B 双轨）、问卷与 AI 分析说明——考评方式对候选人完全透明
- 政策知识视图：知识提炼链产物（政策列表、状态承载、主题总结）的公开化展示
- 候选人个人考评页：凭查询凭证查看自己的评估记录（考核分层、问卷分析）与信任记录（历史行为、背调、推荐信）
- 公平承诺页：成长与合作理念的对外呈现
- **推荐信真实化（P0）**：数据源 mock（`assets/mock/recommendations.json`）→ Provider API（`GET /recommendations/:id`，凭会话凭证）；凭证查询首页（`POST /sessions/verify`）
- **评估/信任记录页**：凭凭证查看记录（`GET /records?type=assessment|trust`）

**为什么推荐信真实化是 v0.1 的核心交付而非加分项**：推荐信是商业化第一个实体交付物，可信度决定商业模式成败；mock 一天不换真实数据流，商业模式就一天是叙事。

## v0.2：统一考评档案

- 单一档案视图：标准 + 过程 + 结果 + 信任合并为候选人自己的完整考评档案
- 导出能力：候选人生成 PDF 证明（推荐信 PDF 导出与分享链接）——阶段三「市场担保」的直接铺垫
- 政策-档案联动：政策变更即时反映在评估口径展示上
- **初始信用档案接入**：历史数据迁移后，platform 租户的考核分层、历史行为记录自动成为推荐信素材

## v0.3+：信用展示与授权

- **授权管理页**：查看"我向哪些企业披露过信用摘要"、可撤销（`GET/DELETE /authorizations`）——多租户信用背书的客户端配套
- 企业付费查证（验证收费点）：企业通过验证入口查证推荐信真伪
- 职业路径追踪反哺评估模型（数据飞轮）
- 多租户信用摘要披露：企业租户开启信用背书后，候选人投递时授权披露摘要

## 技术约定

- Flutter；候选人档案数据模型（freezed）与 Provider API schema 同源，保证评估字段与信任字段同构契约
- 数据源：Provider API（考评标准只读、个人档案凭凭证查询）；凭证 → 会话凭证（JWT）
- 付费链路与证据链路在数据层不交叉（推荐信只凭证据出具）
