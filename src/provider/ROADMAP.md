# ROADMAP — qtrecurit Provider

qtrecurit Provider 是数据服务端（Go）：内部写入考评数据，候选人凭查询凭证自查询。版本目标与并行逻辑见仓库根 `ROADMAP.md`。

## 版本目标

| 版本 | 内容 | 对应产品阶段 |
|------|------|-------------|
| v0.1 | 考评标准只读 API + 候选人档案 API | 阶段一 + 阶段二 |
| v0.2 | 统一档案聚合 + 导出 API | 阶段一 × 阶段二 |
| v0.3+ | 市场担保与信用数据（候选） | 阶段三、阶段四 |

## v0.1：数据服务

- 考评标准只读 API：政策、筛选标准、考核说明——无需登录即可读（透明公开的基础）
- 候选人档案 API：`GET/POST/PUT/DELETE /api/v1/candidates`（评估字段 + 信任字段同构契约）
  - 内部写入：评估记录（考核分层、问卷分析）、信任记录（历史行为、背调、推荐信）
  - 候选人查询：凭查询凭证查看自己的档案
- 存储层：FileStore 本地存储（S3 预留），参照 qtadmin provider 模式
- 基础设施：健康检查、配置管理（环境变量 + 文件）

## v0.2：聚合与闭环

- 统一档案聚合 API：合并评估与信任的单次查询
- 闭环规则服务端化：考核结果沉淀为信任记录、信任数据校准筛选标准
- 导出 API：为候选人 PDF 证明提供数据出口（阶段三铺垫）

## 技术约定

- Go；档案 schema 与 Studio 数据模型同源（契约先行）
- CLI 采集结果通过 API 写入，Provider 不重复造数据
