# ROADMAP — qtrecurit Site

qtrecurit Site 是**对外招聘前台**——招聘启事（岗位要求、报名方式）与招聘数据公开。随多租户平台演进，从量潮静态官网升级为多租户招聘前台（详见仓库根 `ROADMAP.md` 与 `docs/dev-guide/multi-tenant-platform-architecture.md`）。

## 版本目标

| 版本 | 内容 | 对应平台阶段 |
|------|------|-------------|
| v0.1 | 去静态化：岗位数据 API 化 + 线上投递与凭证查询 | 阶段 1（多租户骨架）前端配合 |
| v0.2 | 多租户化：品牌配置化、域名路由、招聘数据公开 | 阶段 2（租户前台） |
| v0.3+ | 信用摘要披露、课堂导流、企业自定义品牌 | 阶段 3（信用背书） |

## v0.1：去静态化与可追踪投递

- 岗位数据 API 化：`positions.ts` 硬编码 → `GET /positions`（租户上下文），岗位维护进人事云工作台
- 线上投递：投递表单（基本信息、求职信、简历）→ `POST /applications` → 生成查询凭证
- 投递状态查询页：凭凭证查进度（已收到 → 初筛中 → 需补充 / 通过 / 拒绝）
- 邮件投递保留为兜底

**为什么可追踪投递是 v0.1 而非 v0.2**：没有结构化投递数据，投递-筛选-结果标注链断在入口，AI 初筛校准集无法持续积累——它是"历史数据复用"持续运转的管道。

## v0.2：多租户化

- 品牌配置 API 化：logo、主题色、slogan、公司简介来自租户配置（样板租户 = 量潮现有内容）
- 域名路由：`recurit.quanttide.com`（样板）与 `{tenant}.jobs.quanttide.com` 同代码分流（复用 `*.quanttide.com` 通配符证书）
- 招聘数据公开：投递统计、岗位分布（对候选人透明的数据公开）

## v0.3：商业化前台

- 信用摘要披露：投递表单的"披露量潮信用摘要"授权开关 + 授权后展示最小化摘要
- 课堂导流入口：一屏之内、以"机会"姿态出现，跳转 qtclass
- 已内推状态：投递状态查询增加推荐去向展示

## 技术约定

- React + Vite；页面渲染全部依赖 API，无本地业务状态（为多租户化准备）
- 租户上下文：域名 → `X-Tenant-ID` 请求头
- 数据模型与 Provider API schema 同源（position、application、tenant_config、credit_summary）
