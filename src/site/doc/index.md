# qtrecurit Site 页面与组件规划

qtrecurit Site 是**对外招聘前台**——招聘启事（岗位要求、报名方式）与招聘数据公开。当前是量潮静态官网；随多租户平台演进（见 `docs/dev-guide/multi-tenant-platform-architecture.md`），Site 升级为**多租户招聘前台**：一套代码，样板租户（量潮）与各企业租户共用，品牌配置由租户提供。

## 页面规划

| 页面 | 路由 | 内容 |
|------|------|------|
| 招聘首页 | `/` | 租户品牌区（logo、主题色、slogan、公司简介）、岗位列表、课堂导流入口、报名指引。详细规划见 [screens/join.md](./screens/join.md) |
| 投递与授权 | `/apply/:positionId` | 投递表单（简历、求职信）+ 可选"披露量潮信用摘要"授权开关；投递成功生成查询凭证。详细规划见 [screens/apply.md](./screens/apply.md) |
| 投递状态查询 | `/status/:token` | 凭投递凭证查询处理进度与初筛结果反馈。详细规划见 [screens/status.md](./screens/status.md) |

## 组件规划

- 租户品牌头：logo、主题色、slogan（来自租户配置，样板租户为量潮）
- 岗位卡片：名称、类别、职责（来自 API，非硬编码）
- 投递表单：基本信息、简历、求职信、信用披露开关
- 凭证卡：投递成功后的查询凭证展示与复制
- 状态时间线：已收到 → 初筛中 → 需补充 / 通过 / 拒绝 / 已内推
- 课堂入口卡：一屏之内、以"机会"而非"广告"姿态出现

## 数据模型

与 Provider API schema 同源，全部按租户上下文（`X-Tenant-ID`）过滤：

- `tenant_config`：租户品牌配置（logo、主题色、slogan、简介）——样板租户为量潮
- `position`：岗位（名称、类别、职责、要求）
- `application`：投递（候选人、岗位、简历、求职信、信用披露开关、状态、查询凭证）
- `credit_summary`：信用摘要（等级、背书状态——仅候选人授权后展示）

## 演进方向

- 现状（v0.1）：静态单页，`positions.ts` 硬编码，报名为邮件说明
- 阶段 1：岗位数据与投递状态 API 化（可追踪投递是历史标注数据闭环的入口）
- 阶段 2：多租户化（域名路由 `{tenant}.jobs.quanttide.com`、品牌配置化），第一个企业客户开通
- 阶段 3：信用摘要披露、课堂导流入口、企业自定义前台品牌
