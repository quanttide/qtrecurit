# 投递与授权页面规划

投递页是候选人进入筛选流程的入口，也是**标注数据闭环的第一环**——投递必须可追踪，后续的筛选结果、录用与否、入职表现才能串成完整标注链（AI 初筛校准集的来源）。

## 现状与问题

- 报名是静态邮件说明：邮件标题"姓名-学校-应聘岗位"，正文求职信、附件简历
- 投递后无凭证、无状态——候选人不知道进度，平台没有结构化投递数据
- 信用摘要披露无入口——候选人无法选择"向企业披露量潮信用"

## 页面结构

### 投递表单

- 基本信息：姓名、学校（对齐邮件标题要求）
- 求职信：意向岗位类型（技术类/产品类/市场类/职能类）或具体岗位 + 三个阐述要点（经验、协作软件、AI 工具认知）
- 简历：上传或粘贴，对齐现有简历规范（简单标准、亮点经历、技能证明）
- 校验：邮箱格式、简历必填、岗位必须开放

### 信用披露授权区（阶段 3，样板租户与开启信用背书的租户展示）

- 可选开关："向企业披露我的量潮信用摘要"
- 说明文案：披露内容 = 信用等级与背书状态摘要，不含原始记录；候选人可随时在 Studio 撤销
- 未授权不影响投递——披露是加分项，不是门槛

### 投递结果与凭证

- 投递成功 → 生成**查询凭证**（token），页面展示凭证卡（复制按钮）
- 提示：凭凭证在投递状态查询页或 Studio 查看进度
- 失败 → 展示具体错误（岗位已关闭、简历格式等）

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 投递表单 | 页面主体（基本信息、求职信、简历） |
| 信用披露开关 | 表单底部（可选、带说明文案） |
| 凭证卡 | 提交成功后（token 展示、复制、查询入口） |

## 数据与契约

- 数据源：`POST /applications`（岗位、候选人信息、简历、求职信、信用披露开关）
- 响应：`application_token`（查询凭证，仅此一次完整展示）
- 模型：`Application`（候选人、岗位、状态、凭证、披露标记）

## 演进
