# 招聘首页页面规划

招聘首页是租户对外的门面：品牌区 + 岗位列表 + 报名指引 + 课堂导流入口。样板租户（量潮）的首页即当前 `recurit.quanttide.com` 的演进版；企业租户首页为同一套代码、不同租户配置。

## 现状与问题

- `positions.ts` 硬编码 5 个岗位（数据工程师、产品经理、商务经理、人事经理、执行助理）——改岗位要发版
- 品牌（"量潮招聘"）、公司简介、报名方式全部静态写入 `App.tsx` / `Join.tsx`
- 报名是静态邮件说明（发到 hr@quanttide.com），投递后无法追踪——投递数据进不了平台，AI 初筛校准集断在入口

## 页面结构

### 品牌区

- 租户 logo、主题色、slogan、公司简介——全部来自 `GET /tenants/:id/config`
- 样板租户默认值即量潮现有内容（slogan：你的创造力，值得被看见）
- 企业租户在人事云工作台配置（logo、主题色、slogan、简介）

### 岗位列表区

- `GET /positions`（租户上下文）→ 岗位卡片：名称、类别、职责
- 岗位维护进入人事云工作台（企业 HR 操作），前台只读展示
- 岗位下架/过期自动隐藏

### 课堂导流入口区（阶段 3）

- 一屏之内、以"机会"姿态出现（如"先学会，再上岗——量潮大数据课程"）
- 跳转 qtclass 课程页，作为流量场的入口
- 样板租户才有；企业租户可配置关闭

### 报名指引区

- 静态指引保留为兜底（邮件投递仍支持），主路径升级为线上投递（见投递与授权页）

## 组件明细

| 组件 | 使用位置 |
|------|---------|
| 租户品牌头 | 页面顶部（logo、slogan、主题色） |
| 岗位卡片 | 岗位列表区（名称、类别、职责、投递按钮） |
| 课堂入口卡 | 品牌区与岗位区之间（slogan、课程链接） |
| 报名指引块 | 页面底部（线上投递入口 + 邮件兜底说明） |

## 数据与契约

- 数据源：`GET /tenants/:id/config`、`GET /positions`（只读，租户上下文）
- 模型：`Position`（名称、类别、职责、是否开放）
- 无本地状态：页面渲染全部依赖 API，为多租户化做好准备

## 演进

- v0.1：岗位数据 API 化（去掉 `positions.ts` 硬编码），静态品牌保留
- 阶段 2：品牌配置 API 化，域名路由 `{tenant}.jobs.quanttide.com`
- 阶段 3：课堂导流入口、招聘数据公开（投递统计、岗位分布）
