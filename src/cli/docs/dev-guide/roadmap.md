## 定位

CLI 的定位是**数据采集管道**，不是招聘流程的执行者。平台的业务本体是 Provider（多租户后端原型），招聘前台是 Site，候选人窗口是 Studio——CLI 为它们采集数据。三端角色与商业模式见 `docs/dev-guide/` 下的推荐服务化文档链。

判断依据是两次已经记入档案的失败（札记 2026-10-12）：「尝试直接去做招聘平台，发现失败了，因为招聘的流程变动很大，找不到稳定的结构。之后又尝试去做人事，也失败了」。CLI 死掉的四命令（survey/invite/exam/interview）编码的正是「问卷→进群→笔试→面试」这个具体流程，流程一变工具就作废——2026-10-29 移除的 1591 行就是代价。

由此立一条铁律：**流程入手册，资产入代码。** 流程是易变的，用文档承载（见手册 `qtrecurit/workflow/`）；资产是稳定的，用代码承载（推荐信、历史数据、信用记录）。凡是编码具体招聘流程的命令都不再出现；保留的命令只服务数据资产。

**邮件驱动招聘流程停用。** access 域四命令（survey/invite/exam/interview）、模板系统与 cache 命令整体移除：问卷流程废弃，固定笔试已由选题制考核取代，招聘只做撞墙体验、用规则不用人。
