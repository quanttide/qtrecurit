# AGENTS.md

## 架构思路：接管的分离

```
                     status.rs（编排）
                    ┌──────────────────┐
                    │                  │
  connect（接）──────→  human（管）──────→  stdout（用）
                    │                  │
                    └──────────────────┘
```

### connect — 接

连接外部数据源，拿到原始数据。不关心数据拿来干嘛。

- 当前：Lark 招聘邮箱（`lark-cli mail` 子进程）
- 未来：飞书审批、企微消息等
- 越轻越好：只管协议，不碰业务逻辑

### human — 管

加工成业务信息。不关心数据从哪来。

- 原始邮件 → 岗位分布、投递趋势、漏斗
- 越纯越好：只管计算，不碰外部依赖

### 上层 — 用

编排管线。只关心顺序，不关心实现。

- 当前：`status.rs`（connect 拿 → human 加工 → funnel 补充 → stdout）
- `funnel.rs` 独立是因为它不依赖 human 的内部结构，只消费 `MailItem`

## 实现原则

- **trait 只出现在测试需要 mock 的地方**。唯一实现的 trait 说明不值得抽象，内联掉。
- **配置从外部加载，不硬编码**。岗位规则走 `profile/connect/rules.json`，改规则不重编。
- **输出目标是 stdout Markdown**。不做格式之外的任何事——可以 pipe 到文件、转发飞书、粘贴文档。
- **一个命令做完整的事**。`qtrecurit status` = 拉邮件 + 分类 + 统计 + 报告，一步完成。
- **函数而非 class，文件而非模块**。纯函数，数据进来 Markdown 出去。同类功能放一个文件，不提前拆分。
