# 推荐服务化产品设计

招聘商业化的核心决策：**推荐是服务，不是信用销售**。源自 2026-08-17 决策（[产品日志](https://github.com/quanttide/quanttide-journal-of-product-development/blob/main/qtrecurit/2026-08-17.md)、[商务日志](https://github.com/quanttide/quanttide-journal-of-business-development/blob/main/qtrecurit/2026-08-17.md)），承接 ROADMAP 阶段三（品牌商业化）的先导设计。

## 背景

- 市场是企业方市场，企业生存艰难 → **企业不是付费方**，是企业资源
- 整个市场招聘服务火热，但只有流量、缺少信用 → 竞争点在于「信用」
- 商业模式与一般招聘平台**完全相反**：一般平台把企业当客户、候选人当商品；我们把**企业当资源（免费）、候选人当资产（信用凭证）**
- 收入来源只有一个方向：候选人的付费（课堂学费 + 推荐服务费）。课堂导流本质上是收候选人的钱，这是唯一的收入引擎，不可排除

## 核心决策

### 1. 推荐是服务，不是卖信用

推荐与大部分招聘工具一样：**收的是服务费，交付的是服务**（匹配、内推、推荐信、过程反馈），而不是结果担保。推荐不是「把信用卖出去」，而是提供一套可交付的推荐服务。

### 2. 付费与推荐结果隔离

钱买的是「**成为可被推荐的人的过程**」（课堂学习、实训、开源项目参与），不是推荐本身：

- 课堂学费 → 产出真实能力证据的加工过程
- 推荐信 = 加工完成后凭证据出具的**质检报告**，不是商品
- 付费买不到证据，证据只能靠干活挣——机制上隔离，信任场不因收费而崩

### 3. 按交付收费，不按结果收费

- 「服务费」对应服务过程（做了内推、出了推荐信、给了反馈），不对应「包你拿到 offer」
- 结果担保是招聘服务被整治的重灾区（付费内推、保 offer、培训贷），守住这条红线就是守住信用资产本身
- 产品结构天然支持这一点：课堂 + 证据 + 服务费，交付物是真实存在的

## 商业模式结构

| 端 | 角色 | 得到什么 | 付费 |
|----|------|---------|------|
| 候选人 | 付费方 | 课堂学习 + 凭真本事挣推荐资格 | 课堂学费、推荐服务费 |
| 企业 | 资源方 | **免费**获得被验证过的人才 | 无（永远免费——稀缺供给，不赶走） |
| 量潮 | 平台方 | 课堂学费 + 信用复利 | — |

### 场域与导流

- 两个场域：**流量场**（课堂）与**信任场**（招聘）。按取舍原则**信任优先**——业务形态决定信用是这个模式的根基
- 边界划分（3 个 AI 建议一致）：**课堂作为导流入口，主体功能做在招聘平台**
  - 课堂放「入口级」信息：一屏之内、以「机会」而非「广告」的姿态出现
  - 招聘平台承载完整功能：推荐、内推、推荐信、信用档案
- 月度招聘形成范例后被市场充分利用，是**零成本导流**：量潮招聘承接市场流量，再往课堂变现

### 壁垒

- 推荐渠道本身太容易复制，护城河在**信用复利**：推荐出去的人表现越好，量潮的信用越值钱，导流回课堂的能力越强
- 推荐短期增加流动性（把人才送往更好的去处）是正常成本；壁垒建立在「在量潮积累的信用在量潮生态里最值钱」，而不是「你挖不动」

## 产品机制

### 推荐信：商业化的第一个实体交付物

推荐信的可信度决定整个商业模式的成败，v0.1 的核心交付，不是加分项：

1. **真实数据流**：CLI 采集行为记录（开源贡献、实训表现、评估记录）→ Provider 存储与聚合 → Studio 生成可验证推荐信
2. **从 mock 到真实**：当前 `src/studio` 推荐信为 `assets/mock` 数据，需替换为上述数据流
3. **可公开、可验证**：推荐信由行为记录、评估记录半自动生成，付费链路与证据链路在数据层**不交叉**

### 三端产品职责

- **Site**（对外招聘门户）：承接市场流量的入口，招聘启事与数据公开；课堂导流的跳转节点
- **Studio**（候选人透明窗口）：候选人查看自己的评估记录、信任记录与推荐信
- **Provider**（数据服务端）：存储与聚合证据，推荐信生成的权威数据源
- **CLI**（数据采集）：把行为记录持续喂给 Provider

### 数据流

```
CLI 采集行为记录 → Provider 存储聚合 → Studio 生成可验证推荐信（候选人自取）
                        ↑
        课堂/实训/开源贡献（付费链路，产出证据的过程）
```

付费链路与证据链路分离：付费决定「能否进入加工过程」，证据决定「推荐信内容」。

## 实施路径

1. **先跑内部闭环（v0.1）**：月度招聘 → 评估记录 → 真实推荐信 → 送出第一批人。团队流动性强，本身就是第一批真实数据的来源；数据没积累之前，商业模式只是叙事
2. **企业合作从释放的资源开始**：团队流动的人才是现成的「可推荐资源」，用招聘形式去找企业方合作
3. **导流变现**：Site 承接流量 → 课堂变现 → 信用复利反哺招聘

## 风险与边界

| 风险 | 应对 |
|------|------|
| 结果担保/付费内推红线（国内整治重灾区） | 按交付收费、不按结果收费；付费与推荐结果隔离 |
| 信任场因收费贬值（「推荐是买来的」） | 付费买过程不买结果；推荐信只凭证据出具，公开可验证 |
| 优秀人才被自己的推荐信送走 | 接受短期流动性，壁垒建在信用复利而非留人 |
| 先有鸡还是先有蛋（无企业资源、无信用数据） | 内部闭环先跑通，再对外讲故事 |

## 决策记录

- 2026-08-17：推荐服务化三决策（服务非信用、付费与结果隔离、按交付收费）
- 2026-08-17：课堂=导流入口、招聘=主体（AI 一致建议，信任优先）
- 2026-08-17：排除「收企业钱」——企业是资源方，永远免费
